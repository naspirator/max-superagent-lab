## 2. Архитектура новой реализации

Один бот, один токен, один polling. Режимы `WORK` и `TEST` в одном процессе,
но с разными хранилищами:

- рабочий: `finance.db`, `sheets_v3`, `ocr_v3`;
- тестовый: `max-finance-stage/test-mode/test_finance.db`,
  `test-mode/input`, `test-mode/confirmed`, без Google Sheets;
- переключение `/test` / `/work`, рабочий черновик не теряется;
- тестовая база создаётся один раз и копирует сотрудников и обозначения из
  рабочей БД только на чтение.

Новые модули: `model`, `money`, `aliases`, `line`, `ocr`, `ensemble`, `store`,
`training`, `ui`, `handlers`, `integration`.

В `bot.py` только три точки подключения: импорт, ветка в `process_photo`,
включение router в `main`. Остальные рабочие модули не изменены.

Подробно: `docs/ARCHITECTURE.md`.

## 5. Новые функциональные элементы

1. **Режим MAX FINANCE TEST** — `/test`, `/work`, отдельная БД, отдельные
   черновики, отдельная база примеров.
2. **Автоматическое чтение структуры** — заголовки Б/Н и Нал, выплаты
   сотрудникам, расходы, долги, Итог, безнал/нал, зачёркнутые и исправленные
   значения.
3. **Программная арифметика** — модель возвращает слагаемые и знаки, сумма
   считается только кодом (`money.signed_total`).
4. **Линия** — сохранение по SHA фото, ручное управление, автопредложение,
   игнорирование всего выше линии.
5. **Словарь** — П, Р/R, В/V, Т, Д, Л, ДИМ, полные имена, частичное написание,
   латинские гомоглифы; добавление/удаление/переименование; конфликт не
   разрешается автоматически.
6. **Полное ручное редактирование** — сумма, каждое слагаемое, знак, сотрудник,
   буква, категория, источник, добавление, удаление, разделение, объединение,
   порядок, дата, линия, повторное распознавание, undo, отмена отчёта.
7. **Итоги категорий** — вычисленные и ручные; расхождение показывается,
   выплаты сотрудников не меняются.
8. **База подтверждённых примеров** — фото, исходный OCR, исправленный и
   подтверждённый результат, типы ошибок, дата, версия движка; только после
   подтверждения; holdout исключён; backup/export.
9. **Изоляция** — тестовый пакет не импортирует Google-модули, рабочие команды
   и рабочие callback-кнопки блокируются в тестовом режиме.

Superagent — существующий сервис `dsh-superagent` в WSL-дистрибутиве
`Ubuntu-Superagent`, панель `http://127.0.0.1:3082`. Сервис запущен:

автор которых совпадает с логином агента (`if sameName(item.user.login, login)

поэтому self-authored Issue #39 не становится тикетом. Независимый отзыв
Superagent фактически не получен; это зафиксировано, а не заменено собственной
оценкой.

## 15. Известные ограничения и оставшиеся ошибки

1. Точность OCR на рукописном почерке недостаточна для автоматической сдачи:
   0/5 полностью правильных отчётов, сотрудники 52,6%.
2. Новый механизм не улучшил recall сумм относительно старого (89,7% против
   89,7%); улучшение только в структуре и категоризации.
3. Автопоиск линии на рукописных Б/Н ненадёжен; ручное управление обязательно.
4. Старый OCR нестабилен между запусками (86,2–93,1%).
5. В `20261123` выплата Т ~7 000 не подтверждена; в эталон не включалась.
6. `Итог` не модернизировался и не создаётся автоматически.
7. Ручной итог категории не распределяется по сотрудникам; показывается
   расхождение.
8. Живой Telegram не тестировался из-за запрета второго polling.
9. Скриншоты — макеты, не реальные снимки.
10. Независимая проверка Superagent заблокирована особенностью GitHub-источника
    (self-authored Issue не принимается); ChatGPT дал REVISE в цикле 1,
    повторная передача исправлений технически не завершена. APPROVE нет.
11. Дообучение весов не выполнялось: используется база подтверждённых примеров
    как retrieval-подсказка.
12. `json-repair` нужен для устойчивого разбора JSON модели; при установке
    добавляется в venv.

## 16. Инструкция по откату

Полная инструкция: `docs/ROLLBACK.md`.

Кратко:

- код: `APPLY=1 sh ~/rollback-production.sh <архив>` — восстанавливает только
  код, база и настройки остаются;
- база: `APPLY=1 RESTORE_DB=1 ...` — только с отдельным подтверждением, теряет
  отчёты после копии;
- тестовый режим: удалить `max-finance-stage/maxfinance_test` и вернуть
  `bot.py` из архива;
- перед откатом скрипт сам делает `pre-rollback-*.tar.gz`;
- после отката проверить `sv status`, лог, `/start`, `/day`, фото и линию.

Резервная копия проверена: `reports/backup-verification.json`.
